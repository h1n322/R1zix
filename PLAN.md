# 📋 План розвитку RiskMate (Наступна сесія)

Ось пропонований план завдань, щоб ми могли продуктивно продовжити роботу завтра. Він базується на вирішених сьогодні проблемах та архітектурних потребах проекту.

## 🎯 Пріоритет 1: Стабільність даних та обробка Rate Limits
Сьогоднішня ситуація з "фейковими" $125 показала, що `yfinance` має жорсткі ліміти.
1. **Прозорість Mock-даних:** Замість того, щоб Python "тихо" підміняв дані на випадкове блукання (Mock) при блокуванні від Yahoo, варто додати прапорець `is_mock: true` у відповідь API. На фронтенді ми покажемо попередження: *"⚠️ Увага: перевищено ліміт запитів до біржі, відображаються демонстраційні дані"*.
2. **Резервні джерела даних (Fallback):** Додати інтеграцію з безкоштовними API (наприклад, AlphaVantage, Tiingo або Financial Modeling Prep) як запасний варіант, якщо Yahoo Finance тимчасово не працює.
3. **Оптимізація Redis-кешування:** Перевірити, чи кеш не зберігає помилки, та налаштувати різні TTL (час життя кешу) для активних сесій.

## 🎨 Пріоритет 2: UI/UX Графіків та Дашборду
1. **Динамічний масштаб графіка за замовчуванням:** Зараз графік після завантаження завжди скидається на "3М" (3 місяці). Треба зробити так, щоб графік автоматично вибирав масштаб, який відповідає обраному повзунку (наприклад, якщо обрано "5 років", одразу активувати кнопку "Всі").
2. **Індикатори завантаження (Skeleton Loaders):** Покращити візуальний відгук під час розрахунку Монте-Карло, щоб користувач розумів, що відбувається масивна симуляція (замість простого лоадера).

## 🧠 Пріоритет 3: Розширення функціоналу (Risk Engine & Portfolio)
1. **Уніфікація Markowitz Portfolio:** Зараз портфельна оптимізація (Markowitz) йде дещо окремим шляхом. Варто переконатись, що портфельні запити також повноцінно використовують новий Python Data Gateway для історії та новин.
2. **Бектестинг (Backtesting):** Протестувати та фіналізувати ендпоінт бектестингу (`/api/simulation/backtest`), який дозволить порівнювати прогнозні моделі ризику (VaR) з реальними історичними просадками.

## 🔒 Пріоритет 4: Інфраструктура та Бізнес-логіка
1. **Stripe та Pro-доступ:** Перевірити логіку обмеження "Lookback > 3 років лише для Pro". Переконатись, що інтеграція з платіжною системою працює коректно і блокує преміум-функції для Basic користувачів належним чином.
2. **Генерація PDF звітів:** Перевірити, чи коректно працює `PdfReportService` у C# після переходу на Python-мікросервіс для даних.
